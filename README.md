# scoutseo.app

The website for [Scout](https://scoutseo.app) — local SEO and marketing audit
software for Mac.

Static HTML, no build framework, no JavaScript. Pages are generated by Python
scripts and committed, so what is in `site/` is exactly what is served.

## Build

```bash
python3 scripts/build.py     # render every page + robots.txt + sitemap
python3 scripts/lint.py site # quality gate — must pass before shipping
```

`build.py` writes `site/`. `lint.py` blocks three things, each of which is a
real ship-blocker learned from a live programmatic set:

- **VOICE** — stock AI-slop phrases and the "not just X, it's Y" construction.
- **THIN** — under 600 words of body text. Section hubs and legal pages are
  exempt, because padding navigation to clear a word count makes it worse.
- **DUPLICATE** — near-identical 8-word shingles across pages. This, not
  thinness, is the actual flag risk: programmatic sets drift toward one
  template. Shared nav and footer are excluded, or every well-templated site
  looks like a duplicate farm.

## The Index

`/index/` is the data moat: a measurement of which real websites let AI search
crawlers read them. Every published figure comes from
`scripts/collect_index.py`, which ships alongside its input list
(`data/sites.txt`) so anyone can re-run it and get the same answer.

```bash
python3 scripts/collect_index.py data/sites.txt data/index-2026-08.json
```

One request per host, serialised with a delay — a smaller footprint than a
single person visiting a homepage.

Re-run it periodically. Recurring measurement is freshness and brand mentions at
near-zero cost, and it is only a moat while it stays trustworthy: publish the
numbers that are unflattering too, and never publish one that was not measured.

## Structure

```
scripts/render.py       page shell — head, styles, nav, footer, schema
scripts/articles/*.py   authored bodies, one module per page or group
scripts/build.py        renders everything, writes robots.txt + sitemap
scripts/lint.py         the quality gate
scripts/collect_index.py  Index data collection
site/_data/*.csv        entity tables driving article ideas
site/                   the generated site (committed, served by Pages)
data/                   Index datasets (published)
```

`render.py` owns chrome and never generates prose. Every body is written by
hand. Sharing chrome is fine; sharing phrasing is what reads as spam.

## Rules for new articles

1. Answer in the first two sentences. No preamble.
2. A real measured number, with where it came from.
3. At least one place a competitor is the better choice. A page that never
   concedes anything is discounted by readers and models alike.
4. Varied sentence length. Fragments are fine.
5. Structure that follows the topic, not a shared six-heading skeleton.
6. Never a number we did not measure.
